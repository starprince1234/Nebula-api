NEBULA · USER GUIDE

从注册到可用 API Key，按角色完成每一步

Nebula 将模型访问放在明确的组织、项目、模型白名单和双级审批边界内。本手册按真实页面和按钮说明操作，不要求用户记忆接口地址。

学生

注册后选择组织、项目和模型，提交 Key 申请；审批完成后一次性领取。

导师

先申请负责项目，再审核该项目中的学生 Key；可查看并撤销已生效 Key。

老师

维护组织、项目、导师、供应商、模型与 Binding，并执行 Key 终审。

页面入口登录成功后，系统按账号角色进入默认页面：学生进入“申请密钥”，导师进入“审核密钥”，老师进入“审批密钥”。侧栏只展示当前角色有权限的页面。

一、统一登录 / 注册

Nebula 使用同一个登录页面识别三种角色。学生和导师可以公开注册；老师账号由系统初始化或由已有老师邀请后激活。

1. 登录控制台

1

填写邮箱和密码

在“邮箱”输入注册邮箱，在“密码”输入当前密码。邮箱格式由浏览器校验，密码不会在页面上明文显示。

2

需要时点击密码右侧的眼睛按钮

眼睛图标用于“显示密码”；再次点击会切换为“隐藏密码”。它只改变当前输入框的显示方式，不会修改密码。

3

点击“登录”

提交期间按钮显示“登录中…”并禁止重复提交。成功后按照角色跳转到对应工作台；如果是从受保护页面跳转到登录页，成功后会回到原页面。

登录后的默认落点
  • 学生：申请密钥
  • 导师：审核密钥
  • 老师：审批密钥
账号状态

被停用的账号不能继续使用受保护页面。遇到“账号已被停用”，请联系老师处理；不要重复注册同一邮箱。

2. 注册学生 / 导师

在登录页点击“注册学生/导师”，进入“创建账号”。注册页面顶部的两个切换按钮决定注册角色：

页面元素用途与操作注意
“学生” / “导师”选择要创建的角色。默认选中“学生”。切换邮箱或角色后，之前发送的验证码不再适用于当前组合，需要重新发送。
姓名填写显示名称，最多 64 个字符。必填。
邮箱填写可收信的邮箱。全局唯一；提示“该邮箱已注册”时直接登录或找回密码。
密码 / 确认密码输入并再次确认密码。长度必须为 12–128 个字符，两次必须一致。
“发送验证码”向当前邮箱发送注册验证码。发送后按钮进入 60 秒倒计时。倒计时结束前不能重复发送；验证码不会在页面或接口响应中显示。
邮箱验证码填写邮件中的验证码。验证码过期或错误时，重新发送后再提交。
“注册”提交账号创建。成功后跳转登录页。注册期间按钮显示“注册中…”并禁止重复点击。
“← 返回登录”放弃注册并返回登录页。不会创建账号。
选择角色 → 填写姓名、邮箱和两次密码 → 发送验证码。
收到验证码后填写“邮箱验证码”，确认邮箱和角色没有改变。
点击“注册”，看到成功提示后使用新账号登录。

3. 老师激活账号

老师不能在公开注册页自行创建。已有老师在“组织管理”点击“邀请老师”，填写对方邮箱后发送邀请。被邀请人打开邀请链接进入“激活老师账号”。

1

确认邀请 Token

如果邀请链接已带 Token，页面会自动使用它；如果没有，填写“邀请 Token”。邀请无效或已过期时，需让邀请方重新发送。

2

填写姓名、设置密码、确认密码

密码同样要求 12–128 个字符且两次一致。

3

点击“完成激活”

成功后返回登录页。按钮在激活请求期间显示“激活中…”，不要重复点击。

4. 找回密码

登录页点击“忘记密码”，流程分两步：

  1. 第一步填写“注册邮箱”，点击“发送重置验证码”。
  2. 第二步确认邮箱，填写“验证码”“新密码”“确认新密码”，点击“重置密码”。成功后返回登录页。
安全提示

不要向任何人提供密码、验证码、JWT、refresh token 或完整 API Key。系统不会在页面上显示这些敏感值，也不会通过 URL 查询参数传递它们。

5. 认证页常见问题

现象处理方法
收不到注册 / 重置验证码检查垃圾邮件，确认邮箱拼写；发送按钮有 60 秒冷却，等待后再试。仍失败时联系管理员检查邮件服务。
提示邮箱已注册不要重复注册。回到登录页直接登录；忘记密码则使用“忘记密码”。
提示验证码错误或过期使用最近一次邮件中的验证码；重新发送后只使用新验证码。连续失败过多可能暂时锁定。
提示邮箱或密码不正确确认登录角色无需手动选择，系统按账号识别角色；检查输入后仍失败就走找回密码。
老师邀请链接打不开或激活失败确认 Token 完整、没有过期；让现有老师在“组织管理”重新发送邀请。

二、密钥申请流程

一个 API Key 的完整链路是：学生提交 → 负责项目的导师初审 → 老师检查模型路由并终审 → 学生一次性领取。任何一步驳回都会结束本次申请，学生需要重新提交新的申请。

先检查前置条件

学生能看到组织和项目，不代表申请一定能提交：项目必须处于启用状态并且已有负责导师；所选模型在老师终审前必须配置为可用并有可用路由。

1. 学生：提交新的密钥申请

登录后进入侧栏 申请密钥。页面左侧是“新申请”，右侧是“我的申请”。按以下顺序填写：

1

点击“刷新”（可选）

重新加载组织、模型和历史申请。如果页面刚打开，系统会自动加载；刷新期间原有内容会保留并显示刷新进度。

2

选择“1. 组织”

下拉框只列出当前可申请的 ACTIVE 组织。选择组织后会加载该组织的项目；如果已经选过模型或填写了新模型草稿，再切换组织会弹出确认框，确认后会清空项目、已选模型和新模型草稿。

3

选择“2. 项目”

项目下拉框只有在选择组织后可用。已停用项目显示“已停用”，没有负责导师的项目显示“暂无负责导师”，这两类项目不能选择。没有可用项目时，需要联系老师启用项目并分配导师。

4

填写“3. 模型白名单”

先使用“搜索可见模型”按名称、model ID 或能力筛选。点击某一模型的“选择”加入白名单；已选模型按钮变为“已选择”，再次点击可取消。白名单总数显示为 当前数量/100，平台模型和新模型合计最多 100 个。

5

需要新模型时点击“申请新模型”

新模型必须在申请 Key 的这个弹窗中添加，不是在“模型广场”里添加。弹窗标题为“申请新模型”，填写完整卡片后点击“加入白名单”。

6

填写“4. Key 名称”并提交

例如 research-key。名称最多 128 个字符；进行中或生效的 Key 名称不区分大小写且不能重复。确认已选择至少一个模型后，点击“提交申请”。

“申请新模型”弹窗中的每个字段

元素如何填写是否必填 / 作用
模型 ID填写供应商实际识别的公开模型 ID，例如 new-lab-model。必填；应保持稳定、唯一。
显示名称填写用户容易识别的名称。必填；用于模型广场、审批和模型卡片展示。
类别选择 text、image、audio、video、multimodal、embedding 或 rerank。必填。
描述补充模型用途、适用场景等说明。可选。
能力 + “添加”输入能力后点击“添加”，也可以在输入框按 Enter。已添加能力会以 chip 显示。至少一项；重复能力不会重复加入。
输入模态 / 输出模态勾选 text、image、audio、video。输入和输出各至少一项。
上下文长度填写正整数。可选；未知时可以留空。
最大输出 Token填写正整数。可选；未知时可以留空。
“加入白名单”校验通过后把模型加入当前申请。若 ID 已存在，系统会复用平台权威配置。未填写完整模型 ID、名称、能力或模态时不能加入。
弹窗关闭按钮关闭弹窗。已经加入白名单的模型仍保留在申请表中；未提交的表单内容不作为申请保存。关闭不等于提交。
新模型的实际处理方式

如果模型 ID 已存在，系统会把它加入当前申请并采用平台的权威卡片；如果不存在，系统会创建为“待配置”，并随本次 Key 申请进入老师后续配置流程。模型申请审批通过并完成配置后，才会出现在学生模型广场。

2. 导师：申请负责项目并完成初审

导师必须先成为项目负责人，才能看到该项目的待初审 Key。导师侧的两个页面都属于密钥流程的前置或审批环节。

2.1 在“项目管理”申请负责项目

  1. 进入 项目管理，点击“刷新”获取组织和项目。
  2. 按组织分组查看项目。项目卡片显示名称、说明和状态。
  3. 对 ACTIVE 且尚未负责、没有待处理申请的项目，点击“申请负责”。提交后按钮变为待审核状态。
  4. 在下方“申请历史”查看项目申请状态和老师意见。申请被批准后，项目按钮变为“查看 ACTIVE Key”。
导师项目关系异常

如果老师批准导师项目申请时提示“导师未加入项目所属组织”，老师应先到“组织管理”分配导师；如果提示导师已经是项目成员，则无需重复审批，刷新页面即可。

2.2 在“审核密钥”完成初审

  1. 进入 审核密钥。列表按最早提交优先，只显示负责项目中的待初审申请。
  2. 使用“搜索申请人”按姓名或邮箱过滤，使用“项目”下拉框按项目过滤；点击“刷新”重新拉取队列。
  3. 点击申请行右侧的“审核”，右侧详情显示 Key 名称、申请人、组织、项目、提交时间、申请模型和每个模型状态。
  4. 通过时可在“审核意见”填写可选意见，点击“通过”。驳回时先点击“驳回”，在确认弹窗中点击“确认驳回”；驳回原因必填且会永久记录。

导师不能代替老师做终审。初审通过后，Key 状态进入“等待老师审核”，学生和老师会在实时连接恢复后看到刷新结果。

3. 老师：为终审准备配置并审批

老师的终审按钮只允许在申请包含的全部模型都已可用、且每个模型都有可用路由时点击。建议按“组织 → 项目 → 导师 → 供应商 → 模型 Binding → Key 终审”的顺序准备。

3.1 组织管理：建立申请范围和导师关系

  • 添加组织：填写名称、说明和状态后保存。名称在平台中必须唯一。
  • 编辑：修改组织名称、说明或状态。
  • 分配导师：在弹窗中用“搜索姓名或邮箱”查找 ACTIVE 导师，点击“搜索”，对候选点击“分配”。已加入的候选会显示“已加入”并禁用按钮；需要更多结果时点击“加载更多”。
  • 邀请老师：填写老师邮箱并点击“发送邀请”。这只负责创建邀请，不会自动激活对方账号。
  • 停用 / 启用：停用组织会阻止新的学生申请，但不删除历史成员和记录；停用前页面会要求确认。

3.2 项目管理：建立学生可申请的项目

  • 添加项目：选择所属组织，填写名称和说明，保存后默认为 ACTIVE。
  • 使用“项目名称”搜索、“组织”筛选和“状态”筛选定位项目。
  • 编辑：修改项目名称、说明或状态；所属组织创建后不可更换。
  • 停用 / 启用：停用只影响新的申请，已有成员关系和历史记录保留。
  • 右侧“导师项目申请”列表中，点击“通过”或“驳回”。驳回必须填写原因；通过意见可选。

3.3 在“审批密钥”完成终审

  1. 进入 审批密钥，用“搜索申请人”“组织”“项目”筛选待终审队列；队列按最早提交优先。
  2. 点击某行的“终审”，右侧打开终审摘要。每个模型都会显示模型状态和“路由是否就绪”。
  3. 如果模型未就绪，点击该模型右侧的“配置”，系统会进入“模型管理”并定位到对应模型。
  4. 在模型管理补齐模型元数据、供应商和 Binding，确认模型为 ACTIVE、供应商为 ACTIVE、至少一个 Binding 为 ACTIVE 且协议 Adapter 正确。
  5. 返回终审详情，确认所有模型均为 ACTIVE 且路由就绪。可以填写“终审意见”，驳回时必须填写原因。
  6. 点击“终审通过”，在确认弹窗中点击“确认”。通过后学生会自动加入目标组织和项目，Key 进入“等待领取”。
“终审通过”按钮按不了：完整解决方案
  1. 看右侧“模型就绪检查”，找到显示“未 ACTIVE”或“路由未就绪”的模型。
  2. 点击该模型旁边的“配置”，进入“模型管理”。
  3. 先在“供应商管理”确认供应商已创建、凭据已配置且状态为启用；再在模型详情中新增正确的 Binding，设置上游模型名、对应 Adapter、优先级和 ACTIVE 状态。
  4. 保存后确认模型卡片显示“已就绪”，必要时将模型启用；返回“审批密钥”刷新并重新打开申请。
  5. 所有模型都通过检查后，“终审通过”才会变为可用。不要通过修改浏览器页面状态来绕过检查。

4. 学生查看状态、领取和保存 Key

4.1 “我的申请”中的按钮和信息

元素作用
状态徽标显示“等待导师审核”“等待老师审核”“等待领取”“已启用”“已驳回”或“已撤销”。
进度条按“已提交 → 导师审核 → 老师审核 → 领取生效”显示当前阶段；驳回和撤销会停在对应终态。
“审核状态”打开申请详情，查看组织、项目、模型列表和按时间排列的审核记录。
“一次性领取”只在状态为“等待领取”时出现。点击后先确认，再请求生成/领取完整 API Key。
“刷新”重新加载申请列表。实时连接也只负责提示刷新，权威状态始终以页面重新加载的数据为准。

4.2 一次性领取的正确做法

  1. 点击“审核状态”或直接点击“领取”，确认申请已经是“等待领取”。
  2. 点击“一次性领取”，在确认弹窗中点击“确认领取”。
  3. 弹窗显示完整 API Key 后，立即点击“复制密钥”，并将它保存到安全的密码管理器或应用配置中。
  4. 关闭弹窗。关闭前如果还没有复制，系统会再次确认；确认关闭后，完整明文不会再次显示。
完整 API Key 只显示一次

数据库只保存不可逆的校验信息，页面关闭后也不会提供“再次显示”。复制失败时可手动选中密钥复制；如果已经丢失明文，只能重新提交申请，不能要求后台恢复。

4.3 导师撤销已生效 Key

负责导师进入 项目管理，在负责项目卡片点击“查看 ACTIVE Key”。在弹窗中找到 Key，点击“撤销”，填写必填的“撤销原因”，再点击“确认撤销”。撤销后立即失效且不能恢复，但不会删除学生的组织或项目成员关系。

三、模型管理

模型有两套用户视角：学生通过“模型广场”查看当前可见模型；老师通过“模型管理”维护平台模型元数据、启停状态和供应商路由。学生不能直接修改平台模型。

1. 学生模型管理：模型广场

进入侧栏 模型广场。页面集合包含平台 ACTIVE 的全局常用模型，以及学生已获批或已生效 Key 中关联的模型；因此某个已停用模型仍可能因历史 Key 出现在列表中，并显示真实状态。

页面元素使用说明
“申请新模型贴士”打开提示弹窗，说明新模型应在“申请密钥”阶段添加；审批并完成配置后会自动更新模型广场。它不是新模型创建按钮。
“搜索”按模型名称、model ID 或能力过滤。
“类别”按 text、image、audio、video、multimodal、embedding、rerank 过滤。
“状态”按已启用、已停用、待配置过滤。
模型卡片显示显示名称、model ID、类别、状态、描述和常用标记。
“查看详情” / “收起”展开或折叠能力、输入/输出模态、上下文长度和最大输出 Token。
“没有匹配的模型”说明当前搜索或筛选没有结果；调整搜索词或筛选条件。
学生需要一个还不存在的模型怎么办？

不要在模型广场寻找新增按钮。回到“申请密钥”，选择组织和项目，点击模型白名单中的“申请新模型”，完整填写模型卡片后随 Key 一起提交。

3. 供应商和 Binding：让模型真正可路由

模型卡片上的“已就绪”不仅取决于元数据，还取决于供应商和 Binding。推荐先配置供应商，再回到模型详情创建 Binding。

3.1 供应商管理

页面元素操作规则
“添加供应商”填写名称、Base URL、凭据和状态后保存。凭据会被加密保存，读取时只显示“凭据已配置/未配置”。
搜索 / 状态按名称或 Base URL 搜索，按全部状态或启用/停用筛选。Base URL 必须是有效 URL。
“编辑”修改名称、Base URL 或状态。普通编辑不会回显或携带旧凭据。
“替换凭据”输入新凭据，点击“确认替换”。“按住临时显示”只在按住期间显示输入内容，松开立即隐藏。凭据不会再次显示；确认替换后无法从页面取回旧值。
“启用” / “停用”切换供应商状态。如果停用会让 ACTIVE 模型失去最后一条路由，系统会弹出“无法停用供应商”并列出受影响模型；先为这些模型保留其他有效路由。

3.2 Binding 详情

在模型卡片点击“配置”，进入模型详情弹窗，在 “Bindings” 区域操作：

  • 新增 Binding：选择供应商，填写上游模型名，选择 Adapter，设置优先级和状态，然后保存。
  • 编辑：修改上游模型名、Adapter、优先级或状态；已创建 Binding 的供应商不能在编辑表单中更换，需要新增正确 Binding。
  • 优先级：填写不小于 0 的数字，用于候选路由排序。需要同一模型支持多个协议时，要按协议分别创建 Binding。
  • 状态：只有 ACTIVE Binding 且所属供应商 ACTIVE，模型路由才可能就绪。

4. 模型状态与终审判定

状态页面含义处理方式
待配置模型记录已经存在，但尚未完成可用配置；如果已有就绪路由，卡片会按“已就绪”展示。配置 ACTIVE provider + ACTIVE binding，确认路由就绪。

常见情况解决方案

现象常见根因解决方案
学生看不到可选择的项目组织未启用、项目已停用，或项目尚未分配负责导师。联系老师在“项目管理”启用项目，并在“组织管理”分配导师。学生重新选择组织或点击“刷新”。
学生不能提交申请未选组织、项目、模型或 Key 名称；模型数为 0 或超过 100；新模型卡片不完整。按“1–4”逐项检查。新模型至少填写 ID、显示名称、能力、输入模态和输出模态。
导师审核队列为空导师还不是对应项目负责人，或申请尚未提交到该项目。在导师“项目管理”申请负责；由老师批准后再刷新“审核密钥”。
老师终审按钮不可用申请中的一个或多个模型未 ACTIVE，或没有 ACTIVE provider + ACTIVE Binding 路由。在右侧逐模型点击“配置”，补齐供应商、模型元数据和正确 Adapter 的 Binding；保存后返回并刷新。
停用供应商 / Binding 失败并列出模型操作会使 ACTIVE 模型失去最后一条可用路由。按弹窗列出的 model ID 逐个添加替代 Binding，确认新路由 ACTIVE 后再停用原资源。
模型已在学生申请中，但老师看到的名称或字段不同平台已存在同 ID 模型，系统采用平台权威卡片，不重复创建。老师在“模型管理”打开该模型更新权威元数据；不要创建大小写不同的重复 ID。
申请状态长时间不变当前审批人尚未处理，或实时连接中断。查看状态进度和审核详情；点击“刷新”。实时连接恢复后系统会自动重新获取列表。
提示“申请状态已发生变化”另一位导师或老师已经先完成了操作。刷新页面，按最新状态继续；不要重复提交同一决策。
Key 领取后找不到完整密钥完整明文只在首次领取响应和当前弹窗中出现，关闭后不会再次返回。使用领取时保存的密钥；如果遗失，只能重新申请。不要要求后台恢复明文。
网关提示 model_not_allowed请求模型不在该 Key 的模型白名单，或客户端使用了错误模型 ID。使用网关模型列表中的公开 model ID；学生确认该模型已包含在对应 Key 申请中。
网关提示模型不可用模型、Binding 或供应商被停用，或当前入口没有匹配 Adapter。老师按“模型 → Binding → 供应商”检查状态；不同协议创建对应 Adapter，不要用错误 Adapter 替代。
页面显示登录状态失效会话过期、账号退出、refresh session 失效或账号被停用。重新登录；若账号被停用，联系老师。不要复制浏览器 Cookie 或 Token 给他人。
哪些功能当前不在首期范围内？

当前网站不提供计费、余额、额度、RPM、Token 限制、用量记录、通知中心、模型价格、智能路由、资源删除 API 或旧路由兼容层。页面没有这些按钮是设计范围，不是缺失。

遇到仍无法解决的错误，应该提供什么信息？

请提供页面显示的错误文字、操作页面、资源名称或脱敏的 Key prefix，以及错误发生的大致时间。不要提供密码、验证码、完整 API Key、refresh token、JWT、供应商凭据、数据库 DSN 或加密主密钥。
